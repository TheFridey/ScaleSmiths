# Operational workflows

Applicant -> founder review -> in-principle approval -> recorded legal/agreement/independent-status/operations confirmations -> expiring invitation -> partner activation -> existing Auth.js login.

Partner -> canonical prospect registration -> generic duplicate/suppression check -> saved discovery -> submitted scope -> founder decision -> locked capacity reservation -> immutable approved contract -> acceptance record.

Founder/finance -> verify invoice and actual VAT-exclusive collection with evidence -> idempotent payment event -> exact commission delta -> partner statement -> prepare and manually approve payout with invoice reference -> record external settlement reference -> reconcile. A pipeline stage change never earns money.

Revocation -> disable existing identity and revoke sessions; preserve financial entitlement/audit history. Declined/withdrawn applicants follow approved retention policy. No external email is sent automatically during development. Invitations are copied by authorised founders for safe testing, not dispatched by a provider.

Founder resource publishing makes approved versions available to partners; drafts and internal records never appear in client presentation. Capacity exhaustion defers scope approval without blocking prospect discovery.
