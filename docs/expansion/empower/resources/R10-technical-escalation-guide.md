# R10 Technical escalation guide

| Field | Value |
|---|---|
| Status | `DRAFT` |
| Audience | Partner only |
| Review owner | Delivery founder |
| Sources | Meeting types in `admin/src/lib/expansion-operations.ts`; faq: something-breaks, manage-external-site, unfinished-project, website-migration, dns, domains |
| Review questions | Confirm routes. Confirm "urgent" examples and how founders want to be told about them. |

## Which request to raise

| Situation | Meeting type | Notes |
|---|---|---|
| Migration, platform change, domain or hosting move | `technical_scoping` | Always before price or timeline |
| E-commerce, booking, payments, portals, integrations | `technical_scoping` | |
| A workflow, CRM or system rather than a website | `bespoke_discovery` | See R05 |
| Prospect ready for detail | `joint_sales` | Brief ScaleSmiths first |
| Pricing, payment plans, discounts, contract questions | `commercial_assistance` | Never answer these yourself |
| Reviewing a proposal before it is sent | `proposal_review` | |
| Wanting help with a topic | `training` | Optional |
| Complaint, mistake, legal question, data concern, urgent client problem | `escalation` | Same day |

## Always escalate

- The client's live website, email or domain is broken now. Under an agreed arrangement, ScaleSmiths follows the documented route; without one, ScaleSmiths will say honestly whether it can help.
- Someone offers you passwords. Decline; ScaleSmiths uses delegated or scoped access.
- The client wants ScaleSmiths to take over an unfinished project or a site it did not build (a code and infrastructure review comes first).
- Security incidents, suspected hacking, data loss or anything involving personal data.
- A question you cannot answer from an approved knowledge entry.

## What to include

1. Business name and portal reference.
2. What the client asked, in their words.
3. What you have already said.
4. Relevant facts from the questionnaire (systems, access, deadline).
5. How urgent it is, and why.

## What happens next

ScaleSmiths reviews the request and confirms a time, proposes an alternative or asks for information. Nothing is booked, and no invitation is sent, until a time is confirmed.
