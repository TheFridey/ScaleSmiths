## Enforced boundaries

- Partner workspace requests pass persisted roles, active flags and session versions through middleware and server capability checks. The external role receives only `expansion.partner`. The invitation consumer is an explicit public exception with a same-origin requirement, throttling and one-time hashed credentials. Existing separately authenticated service endpoints remain governed by their own credential checks.
- Partner workspace mutations derive identity from the authenticated account and fence against concurrent revocation using its persisted user row. Opportunities are selected with an owned partner ID. Ledger and payouts read the authenticated profile. PostgreSQL runtime credentials are shared by the admin application, so partner tenant isolation is enforced in application queries rather than by per-partner database credentials.
- Private API responses use no-store. The statement CSV is generated from the caller's already-scoped snapshot. Text cells use the existing `csvCell` formula neutralisation and quote escaping, and the numeric commission cells use integer amounts from the ledger. No arbitrary file or statement endpoint is introduced.
- The public application path validates configuration, same-origin, request size, fields and notice version. It records no founder decisions. Persistence failure forwards only a generic monitoring exception, without request content or raw driver errors.
- Partner materials exposed here are structured text. Their content remains an explicit publication decision. Arbitrary downloads and client document access are outside this feature.

## Release evidence boundaries

The disposable PostgreSQL run used `SS_TEST_POSTGRES_TMPFS=true` with `npm run test:postgres-privileges` and applied 24 web and 73 admin migrations. It performed a real applicant insert as the web runtime, confirmed denial of a founder-owned status write, executed the resource lifecycle trigger as the admin runtime and detected/repaired eight injected grant defects. The privilege policy unit suite passed three tests with `node --test scripts/expansion-privilege-policy.test.mjs`. The host RBAC run passed 57 assertions in two suites, then reported a worker startup timeout for the middleware suite. This timeout does not establish a middleware result. See the final verification report for subsequent runs.

Provisioning must run after the shared migrations to apply the narrowed applicant grant. Verify effective privileges using the canonical script on the isolated target before concluding that an upgrade is compatible. Prior grants do not tighten automatically merely by deploying new application code. A production grant audit, protected-area review and approved activation decision remain external release gates.

Closing the activation switch controls new identities, not continued access by existing identities. An incident that requires removing access must explicitly revoke affected sessions and accounts. A process restart or replacement is needed to apply updated runtime environment configuration consistently across replicas.
